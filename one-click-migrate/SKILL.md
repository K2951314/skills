# 一键换机

git 管代码，加密包管 git 不管、又无法重建的东西。两者合起来才是一个能跑的项目。

本技能做四件事：识别必要数据、补全清单、按场景打包、校验后导入。项目里已经有换机脚本时调用它，不要另写一套 openssl 命令。

## 适用场景

用户要把一个项目从这台开发机搬到另一台，或从一台服务器搬到另一台，且缺的不是 git 里的代码，而是被忽略的密钥、本地配置、数据库或服务器环境。

不用于：整盘备份、同步已跟踪代码、打包依赖目录、把密钥提交进任何 git 仓库。

## 先选场景

第一次开口就确认场景，不要假设「换机」等于把所有东西打成一个包。

| 场景 | 搬什么 | 不搬什么 |
|---|---|---|
| 只换电脑 | 本机 workspace 包 | 服务器上的库和 `/etc` 配置。服务器不动，数据还在那边 |
| 只换服务器 | 服务器 server 包，再上传到新机器的暂存目录 | 本机依赖目录、编辑器目录、流水日志 |
| 两个一起 | 先 server，后 workspace | 不要合成一个包。服务器包并进仓库等于把密钥摆进工作区 |

两个一起换时顺序不能反：先让新服务器起来，再让新电脑连新地址。

## 开始前读什么

1. 项目根若已有换机脚本或恢复文档，先读再动手。智能询价的入口、清单和坑在 `references/example-smart-quotation.md`。
2. 分类边界读 `references/classification.md`。
3. 包格式与哈希读 `references/package-format.md`。
4. 覆盖与停顿点读 `references/conflicts.md`。冲突处理不要凭印象缩写。

## 功能范围

做：

- 从忽略规则和运行依赖里找出「被排除但对运行必要」的文件，写成清单。
- 清单缺失时补全；已有清单时只增量核对，不静默改类别。
- 导出 workspace 包；在用户确认主机后导出 server 包。
- 导入到新电脑；server 包上传到新服务器的暂存目录。系统路径要单独确认才写入。
- 导出和导入都做完整性校验。失败则不出包，或不覆盖。

不做：

- 不打包可重建内容：虚拟环境、依赖目录、缓存、日志、编辑器目录、本技能产物 `.enc`。
- 不替代 `git clone` / `git push`。代码走 git。
- 不自动合并两份数据库，不自动合并两份 env 的键值。
- 不把口令、密钥值、连接串密码写进对话、清单或日志。只报键名、体积、哈希前 8 位。
- 不在用户确认前覆盖已有文件，不在用户确认前改系统目录。
- 不接受新的 SSH 主机指纹，不把口令放进进程参数。

## 清单

清单放在目标项目的 `.migrate/manifest.yaml`，或该项目已有的等价文件。它记录「该搬什么」，不含密钥值，可以进那个项目的 git。加密包不进 git。

没有清单时，生成草稿后停下来给用户看，确认前不要打包：

1. 读 `.gitignore`、`.git/info/exclude`，以及 Docker / systemd / 启动脚本里点名的运行时路径。
2. 用 `git status --ignored --short` 列出被忽略且真实存在的路径。不要 `git add`。
3. 按 `references/classification.md` 分成 `required` / `recommended` / `rebuildable` / `refuse`。
4. 启发式拿不准的，标 `needs-review`，不要归进 `required`。
5. 用户剔除 `required` 必须逐项点头，并在该项记下 `skipped_by_user`。

已有清单时：扫描结果与清单做 diff。新增候选只追加为 `needs-review`。清单里有、磁盘上没有的 `required` 项，按该项的 `on_missing` 决定阻断还是警告。

智能询价不要用通用草稿覆盖 `scripts/pack_workspace.sh`。那个仓库的权威清单就是脚本本身。导出后用 `scripts/env_audit.py` 核对键名。

## 导出

1. 确认场景、清单、口令存放方式。口令不进包；丢了无法找回。
2. 确认产物目录已被忽略。智能询价用 `_换机/`，其他项目默认 `_migrate/`。没有忽略规则时，先提议补上，同意后再打包。
3. 只收清单里用户确认过的项。`refuse` 类即使被点名，也要再确认一次。
4. 数据库连同 `-wal` / `-shm` / `-journal` 一起收。服务器数据库用转储命令生成，不把正在写入的数据文件直接拷走。
5. 加密参数、管道、明文不落盘，按 `references/package-format.md`。
6. 出包后立刻解密回管道，重算 sha256。不一致就删除这个 `.enc`，报告失败。
7. 服务器包额外检查转储非空、格式头正确。PostgreSQL 自定义格式以 `PGDMP` 开头。
8. 用对照表收尾：id、类别、体积、哈希前 8 位、输出路径。然后列出「这个包没有、另一侧才有」的键名。智能询价在只换电脑时，必须提醒那 15 个只存在于 `/etc/sq.env` 的键。

服务器导出前额外确认主机、登录方式、远程路径。SSH 用 `BatchMode=yes`。拉下来的明文只活在临时目录，打包后删除。对话里不回显远程文件内容。

## 导入

1. 先把包解到空的暂存目录，明文 tar 不落盘。按内容判断 `workspace` 还是 `server`，不看文件名。两类标记同时出现时视为 server。
2. 核对 manifest 项数与 sha256。失败的项不写入目标。
3. 拒绝 `..`、绝对路径、盘符、指向包外的符号链接。
4. workspace 包：再问一句是否合并进项目根。默认只写入目标处还不存在的文件。覆盖规则见 `references/conflicts.md`。git 已跟踪的路径一律跳过。
5. server 包：禁止合并进仓库。上传到新服务器暂存目录后，给出键名级 diff，以及要改的地址类变量（如 `DATABASE_URL`、对外来源）。写入 `/etc` 或重启服务前单独确认。
6. 写入用临时文件加校验再替换。替换前把旧文件备份到产物目录的 `backup-<时间戳>/`。失败则从备份拷回。
7. 导入后列出包外还要做的重建步骤：虚拟环境、依赖安装、版本对齐、验证命令。验证失败就停，不自动重导。

## 必须确认

没有当次明确答复就停：

- 场景是换电脑、换服务器，还是两个一起
- 清单终稿，尤其是剔除 `required` 或纳入 `refuse`
- 导出/导入口令（导出输入两次；屏幕不回显）
- 服务器主机与远程路径
- 覆盖方式：全部跳过 / 逐项 / 全部覆盖
- workspace 包是否写入 git 工作区
- 补忽略规则、删除明文残留
- 把服务器配置写入系统路径或重启服务

## 收尾报告

每次操作结束用短表，不要复述文件内容：

- 场景与包类型
- 产物路径或导入目标
- 写入 / 跳过 / 失败已回滚 的项数
- 校验是否通过
- 包外仍需人工做的一步（只列下一步）
