# 冲突、覆盖与确认

默认不覆盖已有文件。用户没点头之前，导入只允许写到空目录或临时解包目录。

## 必须停下来问的步骤

1. **场景。** 只换电脑打 workspace 包，不动服务器。只换服务器打 server 包。两个一起时先 server，后 workspace。
2. **清单。** 列出将要打包的 id、路径、类别、体积。可以剔除 `recommended`。剔除 `required` 必须逐项确认，并记下 `skipped_by_user`。
3. **口令。** 导出时设出口令，并确认丢了无法找回。导入时只问一次，不回显。
4. **服务器地址。** 导出 server 包前确认主机。地址不写入仓库，不写入技能文件。SSH 必须 `BatchMode=yes`。要密码或要首次确认主机指纹时停下来，不要自动接受新指纹。
5. **覆盖。** 默认跳过。只有用户选择全部覆盖、逐项或全部跳过之后才写。
6. **写入工作区。** workspace 包合并前再问一句。server 包不问，直接拒绝合并。
7. **改忽略规则。** `_migrate/`（或项目已有的换机目录）和 `*.enc` 不在忽略规则里时，先提议补规则，同意后再改。不要为了打包去 `git add`。
8. **删除残留。** 发现明文 tar、明文 env、dump 时，先报告路径，确认后才删除。加密包本身可以留着。

## 覆盖策略

| 用户选择 | 行为 |
|---|---|
| 全部跳过（默认） | 已存在的不动；只写入目标处不存在的项 |
| 逐项 | 给出体积、mtime、sha256 前 8 位，问覆盖、跳过或保留双方 |
| 全部覆盖 | 仍要先备份，再覆盖 |

无论哪一档：

- 覆盖前把旧文件复制到 `_migrate/backup-<时间戳>/`，保留相对路径。这份备份不进新的加密包。
- 先写入 `目标路径.tmp-<随机>`，校验 sha256，再替换。替换失败则把备份拷回。
- 不覆盖 git 已跟踪的文件。包里出现已跟踪路径时标为异常并跳过，告诉用户清单可能写错了。
- 数据库若正被占用，拒绝覆盖。先停进程。半截覆盖比缺文件更难恢复。
- 服务器配置不直接覆盖。先写到暂存目录，给出键名级 diff，不展示值。用户确认后才复制到系统路径。需要提权时把命令给用户执行。除非当次明确说「现在就写入」，不要自行 `sudo` 写系统文件。

## 保留双方

- 普通文件：写入 `原名.incoming-<时间戳>`，不替换原文件。
- env 文件：不自动合并键值。只报告「包内有、目标没有」的键名。
- 数据库：不自动合并。两份库合并是业务操作，不是换机操作。

## 导入后的重建

导入成功不等于项目已经能跑。收尾列出包外还要做的事：

- 建虚拟环境，再按锁文件安装依赖。
- 服务器包：改 `DATABASE_URL` 与对外地址，对齐版本锚点，再启动。
- 跑项目自己的验证命令。

验证失败时不要自动重导，不要自动覆盖。报出失败命令和退出码，然后停。

## 对话里禁止出现的内容

- 口令、环境变量的值、连接串里的密码、私钥 PEM、token
- 进程参数里的 `-pass pass:...`
- 把服务器 IP、邮箱、第三方资源 ID 写进可提交的清单或技能更新

可以出现：键名、文件体积、项数、哈希前 8 位、是否缺失、命令是否成功。
