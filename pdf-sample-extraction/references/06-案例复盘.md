# 06 案例复盘

> 三个真实案例，数字都是实跑出来的。看它们比看规则快——规则是从这些事里提炼的。

## 案例一：泰珂洛切削参数重抽（无框线表格 + 三元组）

### 起点

旧产出 `切削参数.csv` 640 行，`vc` 100% 非空，看起来没问题。实际：

| 列 | 非空 | 缺失率 |
|---|---|---|
| vc | 640 | 0% |
| **ap** | **15** | **97.7%** |
| **f** | **15** | **97.7%** |

只有第 1 页（p354，15 行）的列头识别成功，其余 625 行全部丢列。

### 根因（回原文 p356）

表头是三行错落排布，且 `Vc`、`ap`、`f` 在 PDF 里都被拆成两个 span：

```
y=122  切削@428   切深@474   进给量@515
y=131  应用 ISO 工件材料 优先级 断屑槽 材质 速度@428 加工@474 f@507 (mm/rev)@510
y=139  V@416 c (m/min)@421   a@466 p (mm)@471
y=156  低碳钢 首选 JS SH725  50 - 180@424   0.1 - 3@472   0.03 - 0.1@512
```

原文三列数值齐全，CSV 抽成 `vc="50-"`、ap 空、f 空。典型的「首表头硬编码坐标 + 后续页版式微移就失效」。

### 修法（列模型 7 条，见 02 篇）

表头带 + 组/子表头 + 数据 x 聚类定列 + 列冲突定行 + 续行碎片归左邻。

### 结果

| 指标 | 旧 | 新 |
|---|---|---|
| 覆盖页数 | 69 | **70** |
| 数据行 | 640 | **835** |
| ap 非空率（分母=有 ap 列的行） | 2.3% | **100%**（204/204） |
| f 非空率（同分母） | 2.3% | **91.7%**（520/567） |
| 三值齐全 | 15 行 | **168 行** |
| 身份列回原文 | 未测 | 8/8 列 100% |

### 可复用结论

1. **分母必须写清**：拿全部 835 行当分母算 ap 非空率只有 24%，那是错的分母。
2. **三道闸门**挡掉标题误命中（p539/610/755/979）。
3. **块级连坐**隔离 3 个表块（p524 螺纹表、p596/p923 三层表头切槽表），共 20 行。
4. **A/B 独立判**才抓出 p943/p949/p958 的 TPI 列被当 vc。
5. **未完成也要写清**：铣削册 vc 回原文仅 69.1%（多层 ø 矩阵）、钻削册 75 处量级越界
   （多是值域规则问题，微钻 vc=3~6 是真值）、p529/p537 是 3pt 缩印表。

## 案例二：京瓷切削参数（有框线表格 + 四批推进）

### 起点

旧产出 `全量_切削参数.csv` 1394 行，涉及 104 页。实跑体检：

```
加工材料        286   20.5%
硬度             75    5.4%
Vc             1117   80.1%   ← 但 21.6% 是中文段落
ap              457   32.8%
四列齐全           3    0.2%
```

`Vc` 列的真实内容：

```
"，实现软钢至一般钢、铸铁..."      ← 产品介绍正文
"Vc = 400 m/min"                  ← 孤立公式
"精细粒子＋粗粒子的混合结构"        ← 正文
```

**判定：不是参数表**。不是缺字段，是**抽错了对象**——把产品介绍页的文本块按 y 坐标切行了。

### 定分母

按**列名组合**（不是「有没有 vc 字样」）扫全本：

```
候选页 431 → 可解析 237（噪声 194，全是目录/用法说明/材质 lineup）
  full_matrix  2 页 | milling 66 | drilling 21 | milling+drilling 15 | other 133
```

### 四批推进（每批停下报告）

| 批 | 版式 | 页 | 行 | 关键坑 |
|---|---|---|---|---|
| P0 | 11 列全矩阵（三元组） | 353/354/514/515 | 184 | 幻影行 26 行、表头跨列占位、子行 n 由 vc 三元组定 |
| P1-1 | 钻孔 `dc_wide` + `insert_angle` | 356/834/835 | 255 | 一页两张表、第二张右移一列、脚注行混进数据 |
| P1-2 | 刀杆矩阵（3~4 层表头） | 874/875/891 | 1052 | 合并表头只在组首列有文字、★/☆ 是矢量路径 |
| P1-3 | 切槽两行制 | 355 | 40 | 私用区图标字符 `\uf0ab`、牌号带别名、同页三张表 |

合计 **11 页 / 1731 行**，全部过 A/B/C/D 四层。

### 最硬的两条校验

- **p874 维度集合对账**：Vc 组合源 32 / CSV 32，f 组合源 210 / CSV 210。
- **p834 物理不变量**：`n = 1000·Vc/(π·DC)`，212 行里 6 行偏差 ≤5%，2 行 >5%
  → 这 2 条是**样本自身矛盾**（Vc 印 40-100，ø14 转速却印 2750），出清单不改数据。

### 可复用结论

1. **先判「是不是表」**。四列齐全 0.2% 就是明确信号。
2. **有框线就用 `find_tables()`**。手写坐标模型才会遇到「合并单元格跨两行」「材质格堆两个牌号」
   「三元组拆 3 个 span」这三个坑——`find_tables()` 之后它们自动消失。
3. **别一次性铺开 38 页**。K 章 38 个候选页至少 8 种版式，一页一页做通再扩。
4. **样本支持不了的口径要早说**：B 章车削刀片整章 0 处 Vc，车削参数只出现在刀杆页，
   键是「刀杆型号 + 刀片材质 + 工件材料」。

## 案例三：对抗式审查（怎么证明「抽完了」是假的）

### 口径

**不采信任何已有「验收报告」「抽取完成」的结论**，全部回原文重建。
三条互不依赖的线：A 应有（书签+标题）／B 实有（扫盘统计）／C 对不对（逐页 dump 核对）。

### 抓到的 P0（都不是「补字段」能修的）

| # | 问题 | 数字 |
|---|---|---|
| 1 | 泰珂洛技术文档 0 条 | 《UsersGuide》整册 180 页没扫，L 章 132 页全是故障对策 |
| 2 | 泰珂洛切削参数 ap/f 丢 | 640 行里 97.7% 空 |
| 3 | 京瓷材质牌号信息整表错抽 | ISO/加工材料全空；`颜色/主成分/涂层构成` 三列**原文根本不存在** |
| 4 | 京瓷切削参数是正文切片 | 四列齐全 0.2% |
| 5 | 三菱故障对策应有 5 章只做 1 章 | `fault` 列 39 行全空 |
| 6 | OSG 技术文档 98 条只覆盖 19 页 / 1052 页 | 目录 p3 标「技术资料 P.1009～」→ p1010–1018 零产出 |
| 7 | OSG 53% 系列无切削条件页 | 656 个系列里 350 个，wxs 17/17、din7 48/48 全缺 |

### 判定正确的部分（审查也要防过度否定）

- 泰珂洛刀片材质表 15377 行 / 76 牌号，`mark_type` 三态完整（●13282/▲1072/★1023）。
- 京瓷 K 章钻头 1106 型号 vs CSV 1106 行零差异。
- OSG 四册 stock 值域闸门有效。
- 三菱 catalog 页码 1–1857 全部落在样本 1868 页内。
- 三菱 drill_params 的 `vc=3/4/6` 是微钻真实值（dc=0.05–0.16, n=20000）——**值域规则误报**。

### 可复用结论

1. **整册漏扫是最高频的错**。勘察第一步列「册 → 页数 → 章节数」，别只扫目录提到的那几册。
2. **「有产出」≠「有数据」**。1394 行、166 行、98 条这些数字都掩盖了「抽的不是表」。
3. **闸门只报不拦 = 没有闸门**。`cut_page` 覆盖率 53% 缺失存在了很久没人当问题。
4. **审查报告要写「确实正确的部分」**，否则会为了显得严格而误杀好数据。
