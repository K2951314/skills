# 05 交付与接入

> 抽取是上游。产出交给下游之前，先把「这批数据能回答什么问题、不能回答什么」说清楚。
> 说错这一句，下游会按错误口径做产品。

## 一、产出文件（五个，缺一个不算完成）

| 文件 | 粒度 | 用途 |
|---|---|---|
| `主表.csv` | 一行一条记录 | 唯一对外交付物 |
| `明细.csv` | 一个数值一行（`field / col_label / value`） | 多子列不丢信息，排查用 |
| `_低置信.csv` | 被隔离的整块 | 下一轮攻，不进主表 |
| `页清单.md` | 一页一行 | **分母**，验收和下一轮的任务书 |
| `验收报告.md` | — | 见 03 篇模板 |

### 必备列

| 列 | 说明 |
|---|---|
| `page` | PDF 物理页，**每行必填**。没有页码的行等于无法核对（真实出现过 3 条 `page=null`） |
| `_备注` | 每张表都要有。型号截断 / 范围标题 / 疑似误抽都标这里，**不许删除可疑行** |
| `src_row` | 源表格行号，回查用 |

### 页级语义要抽成列

同一页的所有行共享的语义，别丢掉——下游不读就会用错：

| 列 | 例子 | 为什么必须有 |
|---|---|---|
| `scope` | `内径车削加工推荐切削参数(正角型：加工径不足ø10)` | p514 与 p515 **不是同一张表的两半**，是两个独立工况，选型前必须先定加工径 |
| `ap_basis` | `切深为半径值(径向切深)` | 是径向还是直径方向，差 2 倍 |
| `note` | `※SUM等易切钢加工时，PR1725 请设为 Vc=150 以下` | 条件会**推翻**表里的值 |
| `variant` / `chip` | `KTKF 断屑槽 (GQ)` / `ABS15, ABW23` | 同页三张表内容几乎一样，差别只在这里，不抓就是 20 行完全重复 |

## 二、标签归一化（不做下游必漏）

同一标签在样本里因字体/换行出现变体，抽完必须收敛：

| 变体 | 归一 |
|---|---|
| `奧氏体`(繁) / `奥氏体`(简) | 奥 |
| `・`(片假名中点) / `·`(中点) | · |
| `F,U` / `F, U` | `F, U` |
| `( 负角)` 括号内空格 | `(负角)` |
| `…/等` 行末斜杠（换行残留） | `…等` |
| 全角 `（）：，` | 半角 |

京瓷实测：材料从 13 种收敛到 11 种、槽型从 24 种收敛到 23 种。

⚠ **归一化会掩盖真实差异**。收敛前后都要打印对照表，确认「合并的确实是同一个东西」，
不是把 `不锈钢·奥氏体系` 和 `不锈钢·沉淀硬化系` 合并了。

## 三、字段模型别硬套

同一本样本里，不同工序的「切深」根本不是一回事：

| 工序 | 字段 | 说明 |
|---|---|---|
| 车削 | `ap` (mm) | 径向切深 |
| 铣削 | `ap` + `ae` + `fz` | 轴向切深 + 切宽 + 每齿进给，缺一不可 |
| 钻孔 | `Vc` + `f` + `DC` + `rpm` | 加工径是维度，不是属性 |
| 切槽 | **无 ap** | 「切深」= 刃宽，是刀具规格不是切削参数 |

套用车削字段模型去接切槽数据，会得到一列全空的 `ap` 和一个永远算不对的配刀建议。

## 四、接入前必须问清的四件事

抽取产出「能查」和「能用」是两件事。以下四个问题答不出来，就先别接：

### 1. 主键是什么？业务按什么查？

真实教训：京瓷车削刀片（B 章 154 页）**整章 0 处 Vc / 0 处 m/min**。
车削参数只出现在刀杆 / 整体刀具页和全矩阵页，键是**「刀杆型号 + 刀片材质 + 工件材料」**，
不是「刀片型号 + 材料」。产品上要按刀片型号给车削参数，这本样本给不了。

> 抽取前先确认「样本印的键」和「产品要的键」是不是同一个。不是的话，先跟用户对齐口径，别硬做。

### 2. 多行是并集还是重复？

`(品牌, 型号)` 允许**多行**（分页、分刃口、跨页牌号不同），语义是**并集**。
任何清洗脚本按 key 去重重建整表都会静默吃数据（真实踩过：丢 262 行 / 120 个牌号）。

### 3. 关联字段填了吗？

规格表抽得再干净，`series.cut_page`（系列→切削条件页）没填，前端点「切削条件」还是落空页。
真实数据：656 个系列里 350 个（53.4%）查不到推荐参数，其中 WXS 17/17、DIN7 48/48 全缺。
**质量闸门只报不拦，所以这个缺口存在了很久没人当问题。**

> 接入前跑一次「关联覆盖率」：有多少实体能连到下游数据。这比「抽取行数」更能说明可用性。

### 4. 体积与分包

参数表内联进云函数会显著加体积。估算：40 页 × 20~30 行 ≈ +300~500KB（未压缩）可接受；
全量 237 页建议走云数据库，不要内联。多品牌一律按品牌分包。

## 五、代码/命名约定

- 抽取器命名 `_extract_<品牌>_<数据类>[_<版式>].py`，校验器 `_verify_<同名>.py`，
  审查 `_audit_<数据类>.py`，页清单 `_inventory_<数据类>.py`。
- 抽取器里**不写死页码列表**之外的任何东西。页级语义（副标题、脚注、产品名）从页面自动读，
  这样加页只改 `PAGES` 一行。
- 输出目录按 `<品牌>_<数据类>_<日期>/` 组织，同一批的抽取器、校验器、报告、CSV 放一起。
- 旧产出不覆盖：新文件加 `_v2`。

## 六、交接文档要写什么

下一轮接手的人（或下一个 AI）需要的只有三样：

1. **页清单**：哪些页做了、哪些没做、为什么没做（`reject_reason`）。
2. **未完成清单**：每个未完成项写「卡在哪、下一步怎么做」，例如
   「铣削册 vc 回原文仅 69%，版式是 vc/ae/fz/ap × 刀径 ø10·ø12·ø16·ø20 多层矩阵，需跨度模型」。
3. **别再踩的坑**：这一轮新踩的，按「现象 → 解法」写。

别写「已完成 90%」这种话——写清楚哪 10% 没做。
