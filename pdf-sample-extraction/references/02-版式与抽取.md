# 02 版式与抽取

> 版式没有「通用解法」，只有「分类 + 一组已验证的参数」。
> 这一篇给的是参数和判据，不是代码。

## 第一步：先问有没有框线

```python
tf = pg.find_tables()
for t in tf.tables:
    print(t.bbox, t.row_count, t.col_count, t.extract()[:2])
```

- **有完整框线 → 先用 `scripts/extract_skeleton.py`**，它把下面的通用流程都固化了
  （表头自动数行、幻影行合并、子行展开、标签归一化、块级连坐），
  并已用京瓷 4 页全矩阵验证 **184/184 与人工验收过的产出一致**（过程见 `07-骨架验收记录.md`）。
  只有骨架搞不定的版式，才继续往下看这篇自己写。
- **无框线 / 图块 / 表格线只画了部分 → 回到 y 聚类坐标模型**。泰珂洛那套 7 条列模型就是被逼出来的。

别为了「统一」硬用坐标模型，也别为了「省事」硬用 `find_tables()`（认不出就是认不出，
会返回 0 个表或一堆 2 列表）。**同一本样本里两种都可能存在**（京瓷 K 章 38 页能认出表格，
泰珂洛车削册大部分不能）。

`find_tables()` 给的是**单元格文本**，还差三步（骨架已实现，自己写时别漏）：

1. **表头行数自动数**：1~4 行不定，第一行常是跨列占位。写死 1 行会把列名行当数据（产出 0 行）。
2. **行展开**：n 由最可靠列的三元组个数定，其它列有 n 个值一一对应、1 个值整格共用。
3. **幻影行合并**：只有身份列没有参数值的行并回上一行。

## 无框线表格：列模型 7 条（泰珂洛车削册验证）

1. **表头带**：含「切削速度/切深/进给/材质/工件材料…」的行按 y 聚（gap ≤13），
   带底 = 最深关键字行 **+9.5pt**。这个 9.5 是量出来的：表头三行间距 6.6~8.4pt，表头→首数据行 ≥13pt。
2. **组表头 vs 子表头**：`切削速度 / 切深 / 进给量` 是组，`前车 / 背车 / RE:0.8 / 低碳钢` 是子。
   `V`、`c (m/min)`、`a`、`p (mm)`、`f` 是**被拆开的表头碎片**，必须丢掉，否则每页多出 3~5 个假列。
3. **参数列锚点来自数据 x 聚类**（容差 15），不来自表头。
   p596 有 6 个 f 列却只有 3 个子表头——靠表头数不出列数。
4. **子表头→组用「组左界 = 表头 x − 30」切区间**，不用最近中心。
   p357 有 3 个 RE 列，最近中心会把第 3 列错判给「进给」。
5. **身份列按左边缘 x 判，参数列按中心 cx 判**。工件材料这种长文本会向右溢出 20~40pt。
6. **定行靠「列冲突」**：同一列出现第二个值就换行。p357 每行有「主行 + 端面加工行」两套数值，
   y 只差 7pt，任何 y 容差都分不开。
7. **续行碎片归左邻**：`等。`/`，`/`）` 这类碎片按「与左侧 span 间隙 <12pt」归左边那格。
   ⚠ 必须**按视觉行遍历**——同一行里 y 会差 0.1~0.9pt，按 `(y, x)` 排序后相邻的不一定是左边那个 span。

## 阈值表（都是量出来的，别凭感觉调）

| 参数 | 值 | 依据 |
|---|---|---|
| 表头 y 容差 | ≥20pt | `尺寸（mm）` 在 y=127、`RE IC S D1` 在 y=166，差 19pt |
| 表头带底偏移 | +9.5pt | 表头行距 6.6~8.4，表头→数据 ≥13 |
| 合并单元格 y 阈值 | 9.5pt | 换行 8pt vs 数据行距 ≥10.8pt |
| 视觉行聚类 `dy` | **3.2pt** | 行内加粗差 0.22、折行差 2.6、子行差 3.97 三者夹死 |
| 参数表→尺寸表切断 | y 间隙 **>40pt** | 表内行距 ≤25；50 太松（p883 是 45.8） |
| 续行碎片归并 | 间隙 <12pt | 否则工件材料尾巴掉进材质列 |
| 区间值聚合 | x 间距 <9pt | 否则 `0.03` 拼成 `80-1800.03`；反向失败是 `120-` |
| 列名/型号列自适应 | 与表头同名列 x 差 <30 | 双栏页第二表在 x≈160/340，写死会全错 |
| 页面上边界 | y ≥46 | p930/p986 的表头在 y≈50，用 62 会全漏 |

⚠ **聚类必须和「簇首」比，不能和「上一个 span」比**。按相邻间距会链式串行：
135.3→138.8→142.0→143.5 每步都 <dy，两行被串成一行，三元组当场错位。
（有个脚本的注释写「和上一个 span 比」但代码比的是簇首——**以实测为准，注释是错的**。）

## 有框线表格：`find_tables()` 之后的三个必做步骤

### 1. 行展开：n 由「三元组个数」定

一个表格行里有几个子行，由**最可靠的列**决定。切削参数里 vc 必然每行都有，所以：

```
n = len(vc_cell.split('/'))        # vc 的三元组个数
其它列：有 n 个值 → 按 y 顺序一一对应；只有 1 个值 → 整格共用
```

⚠ **别把「子行」理解成「每个牌号一行」**：p353 的 `PR1725 / PR1725` 是同一牌号按
连续/断续拆两行（形态变、牌号不变），p515 的 `TN620/PR1725` 才是两个牌号。
按牌号个数定 n 会在 p353 上直接把行数砍一半。

### 2. 不能对所有列无脑按 `/` 拆

`精加工/(重视光泽)`、`不锈钢/(奥氏体系)`、`HB/≤/300` 里的 `/` 是换行符或文案，不是分隔符。
只有 `form / chip / grade / re / vc / ap / f` 可拆，且拆出的每段必须通过该列的合法性检查
（牌号要像牌号、刀尖 R 要纯数字、形态必须 ∈ {连续,断续,轻断续,强断续}），否则整格共用。

### 3. 幻影行合并

p353/354 的材质列在子行之间有横线，`find_tables` 会把第二个子行的牌号**单独拆成一行**
（只有牌号、没有 vc/ap/f）。这种行要并回上一行（单元格用 `/` 连接）：

```
判据：该行 vc/ap/f 全空，且不是第一行  →  并回上一行
```

既不能当数据行，也不能当错误。两页各 13 行。

## 多层表头（牌号 × 断屑槽 × 刀杆深度）

真实版式（京瓷 p874，4 层表头）：

```
r0:            加工材料 | PR1225 | ... | CA520D | ... | 加工径 | 2D~3D | ...
r1:                      | GM | GH | XM | SM | ...
r2:                      | Vc | Vc | ...
```

**合并表头只在组首列有文字**（牌号只在 col 1/5/9 出现）。做法：

1. 每层表头**向右继承**（空单元格填左边的值），再取**最深**那层。
2. 不继承的后果：Vc 只认出 3 列、f 只认出 2 列，140 行 → 修好后 420 行（差 3 倍）。

### 表头匹配的三个预处理

- **两行表头拼起来**再匹配。p515 的 header0 第 9 格是跨列占位「下限－推荐－上限」，
  真列名「速度 Vc」在 header1；按「header0 空才用 header1」永远找不到 vc 列。
- **去掉 `/` 和空白**：`推荐/断屑槽` → `推荐断屑槽`（p515 是整词，p353 带斜杠）。
- **过滤表头词与单字符**再取最大字号当产品名，否则会抓到 16pt 的**章号 K**。

## 一页多张表

`max(col_count)` 只取到一张，另一张整块丢失（p834/p835 各有两个产品系列的表）。

做法：**遍历所有符合版式的表**，判据用表头关键词，例如
「表头含 `加工材料` + `推荐材质`，且第二行含 `ø`」。
同时注意：第二张表可能**整体右移一列**（p835 表1 首列是空的），
所以材料列要按表头「加工材料」定位，标签列按数据行里的「转速」定位，**都不写死列号**。

## 值解析

### 严格优先

只接受这几种形态，其余一律判为「解析失败」而不是「尽力猜」：

```
单值      123        0.05
区间      120-200    120~200    120 – 200
三元组    250 - 300 - 350          （中间值加粗 = 推荐）
```

**不要写「抽不出区间就 findall 拿数字」**——京瓷 p891 的图例 `: 第1推荐` 里的 `1`
会被当成 `f=1.0`。

### 无锚点正则

```python
NUM_RE = re.compile(r"\d+(?:\.\d+)?")        # 对
NUM_RE = re.compile(r"^\d+(?:\.\d+)?$")      # 错：findall 等价整串匹配
```

带 `^...$` 的 `findall` 会把 `'250 - '` / `' - 350'` 这种「数字+连字符在同一个 span」的格子整条漏掉，
p515 全表直接 0 行。

### 数值判定不能太松

`< 2 mm` 会被 `^[\d<>=~-]` 当成数值（p691/p692 的假 vc）。
要 `^[\d<>=~\-\s.]+$`——不允许出现字母。

### 区间折行

```
判据：上一个值匹配 ^[\d.]+\s*[-–]$ 且 y 差 ≤12pt  →  两行是同一个区间
```

⚠ 裸 `-`（表示「无」）不能当折行，否则整表串行。

### 区间聚合按 x 间距

同一个区间在 PDF 里常被拆成多个 span（`120-` + `180`，或 `0.03` 被拼到 `80-1800.03`）。
按 **x 间距 <9pt 聚合**再拼串，比按 y 聚更准。

## 「不是文字」的信息

这几类 `get_text()` 拿不到，必须单独处理，**且不要看渲染图判断**（低 dpi 下 ● 会因网格线+抗锯齿看着像 ▲）：

| 类型 | 判定 | 案例 |
|---|---|---|
| 私用字体符号 | `rawdict` 里字符是 `\x01`(U+0001) | 泰珂洛 ● 产品型号（`words`/`dict` 拿不到，只有 `rawdict` 有 bbox） |
| 西里尔字母伪装 | 字符是 U+04DA `Ӛ`，字体 `NotoSansCJKjp-Regular` 画成实心三角 | 泰珂洛 ▲ 停产（**不是** U+25B2，全书 57 次全在图例） |
| 矢量路径 | 数线段数：8~12 段 = ★，20 段 = ☆，填充色深棕 (35,31,32) | 泰珂洛 ★ 首选、京瓷 ★/☆ 推荐等级 |
| ISO 材质色块 | 按浅色背景块 RGB + 高度 >20 判分区 | 泰珂洛 P/M/K/N/S/H；短表小分区 h=23，卡 >28 会漏 |
| 图标字体前缀 | 剥 `[\ue000-\uf8ff]` | 京瓷 p355 的 `'\uf0ab 60 ~ 200'`，不剥整个值解析失败 |

**色块 RGB（泰珂洛实测）**：蓝 (0,0.6,0.85)=P / 黄 (1,0.91,0)=M / 红 (0.9,0,0.13)=K /
青绿 (0.22,0.71,0.52)=N / 橙 (0.95,0.59,0)=S / 灰 (0.62,0.62,0.63)=H。
浅色版（京瓷/泰珂洛车削）：(0.63,0.80,0.93)=P / (1.00,0.96,0.59)=M / (0.95,0.60,0.49)=K /
(0.98,0.80,0.53)=S / (0.62,0.85,0.78)=N / (0.80,0.80,0.80)=H。

## 防误命中：三道闸门

抽取器最容易「命中一堆标题当表」。泰珂洛 v2 的三道闸门（缺一不可）：

1. **组表头必须短（≤8 字）且无标点** —— 挡掉「外圆切深槽和切断」「切深槽和切断刀板」
   这类标题（p539/610/755/979 曾全误命中）。
2. **块内必须有「切削速度」或「进给」组** —— 只有「切深」的多半是标题。
3. **块内必须有 `材质/牌号` 或 `工件材料` 列** —— 参数表都有，尺寸表没有。

再加一条**切断**：参数表下面常接一张刀片/刀杆尺寸表，用 **y 间隙 >40pt** 切断。
这条修掉了 `vc='10 - 30 125'`（p930）和 `vc='10 - 30 6.35'`（p883）。

⚠ **别用「按位置切干净」的思路修串味**，两种都实测误伤：
① 用本表 EDP 行横向跨度兜底 xmax → 误砍 p224 的 39 行库存列；
② 要求列头与表头同 y（±2）→ p341/p838 多层表头（错落十几 pt）被整片砍掉。
**在取值端按值域拦才零误伤**（例：库存列只可能是符号 `●▲○◯△■□＊※×-`，取到数字/字母/汉字就丢弃字段）。
