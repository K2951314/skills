# 04 坑总表

> 按「现象 → 根因 → 解法」查。带 ✅ 的是已经验证过的解法，别改成「看起来更优雅」的版本。

## 一、环境与工具

| 现象 | 根因 | 解法 |
|---|---|---|
| `ModuleNotFoundError: fitz`，但明明装过 | Windows `py` launcher 读到 `#!` shebang 会**换解释器**，丢掉 site-packages | ✅ 抽取/审查脚本**一律不加 shebang**，只用 `# -*- coding: utf-8 -*-` |
| 脚本跑完 exit 0 但没有任何输出 | 解释器跑错了（同上），或 stdout 被工具吞了 | ✅ 用绝对路径调 python（`D:/软件/Python/python.exe`）；PowerShell 工具不回显 stdout，要 `Start-Transcript` 落盘再读 |
| Excel 打开 CSV 中文乱码 | 编码 | ✅ 一律 `utf-8-sig` 写出 |
| `find_tables()` 不存在 | PyMuPDF 版本 <1.23 | 先 `fitz.__doc__` 看版本；或用 `page.get_drawings()` 自己找框线 |
| 批量跑几十页时内存涨爆 | 每个 `Page` 对象持有资源 | `doc.close()`，或按页范围分批跑 |

## 二、PDF 读取

| 现象 | 根因 | 解法 |
|---|---|---|
| `get_text()` 返回空 | 扫描件，无文字层 | 先判 `len(pg.get_text().strip())==0`，这类页直接记进页清单标 `no_image`，别硬抽 |
| 书签页码和实际页差几十页 | 印刷页码 ≠ PDF 物理页序 | ✅ 一律用 `get_toc()` 的页序（1-based），目录印的页码只当参考 |
| `words` / `dict` 拿不到某个符号 | 私用字体，字符是 `\x01`(U+0001) | ✅ 只有 `rawdict` 有 bbox 和字符码 |
| 一个「字」在 PDF 里是 3 个 span | 字体切换 / 加粗 / 抗锯齿 | ✅ 按 y 聚合（±2pt）→ 按 x 排序 → 拼串，再切 |
| 竖排文字被逐字切开 | 竖排标签每字独立定位 | 京瓷「金属陶瓷·涂层」被抽成 `CA/金/合/质/涂`。✅ 判据：某列唯一值全是单字 → 是竖排标签，不是数据 |
| 低 dpi 渲染图上 ● 看着像 ▲ | 网格线 + 抗锯齿 | ✅ **禁止看渲染图判形状**，只认字符码 / 矢量路径 |
| 表格里明明有数字，抽取却是空 | 数字是图片（部分样本把参数表印成图） | 该页记 `image_table`，需要 OCR 或人工 |

## 三、版式

| 现象 | 根因 | 解法 |
|---|---|---|
| 只有第一页抽对了，后面全丢列 | 表头坐标硬编码，后续页版式微移 | ✅ 列名归一化 + 同名列 x 自适应（差 <30） |
| 每页多出 3~5 个空列 | 表头被拆成碎片（`V` + `c (m/min)`） | ✅ 丢弃「纯符号/纯单位」的表头碎片 |
| 一页抽出的行数是实际的两倍 | 主表 + 备件表被当成同一张 | ✅ 一页多表必须循环所有表头，按 `(型号, 页码)` 合并 |
| 一页只抽到一张表，另一张整块丢 | `max(col_count)` | ✅ 遍历所有符合版式的表 |
| 产出 0 行，报「xx 不是三元组: ''」 | 表头有**两行**（第一行是跨列占位「下限－推荐－上限」），按固定 1 行把头行当成了数据 | ✅ 表头行数交给脚本自动数（1~4 逐个试，取第一个「必需字段齐全且有数据行能解出值」的）；别让用户数 |
| 值跑到了相邻列 | 长文本右溢 / 组表头判定用最近中心 | ✅ 身份列按左边缘 x 判、参数列按中心 cx 判；组用「组左界 = 表头 x − 30」 |
| 两行数据被合成一行 | y 容差太松 / 按相邻间距聚类链式串行 | ✅ 定行靠「列冲突」；聚类和簇首比 |
| 一个区间被拆成两条记录 | 区间折行（`0.03 -` + `0.12`） | ✅ 上一个值匹配 `^[\d.]+\s*[-–]$` 且 y 差 ≤12pt → 合并；**裸 `-` 不算折行** |
| 区间值拼成一串乱码 | 多个 span 按 y 拼 | ✅ 按 x 间距 <9pt 聚合 |
| 表下面那张尺寸表的数值混进来 | 参数表→尺寸表间隙小 | ✅ y 间隙 >40pt 切断（50 太松） |
| 标题被当成表头 | 标题含「切深」等关键词 | ✅ 三道闸门：组表头 ≤8 字无标点 + 必须有速度/进给组 + 必须有材质或工件材料列 |
| 参数表里混进 `0.8 刀方` 这类规则值 | 版式里本来就有一行「适用刀方」 | ✅ 值域拦（ap 不可能是 0.8 之外还带「刀方」字样） |

## 四、值解析与语义

| 现象 | 根因 | 解法 |
|---|---|---|
| `vc='64 - 12'` 通过了回原文校验 | 那是**每英寸牙数 TPI**，原文确实有 `64-12` | ✅ A/B 两层独立判，B 层 `min<max` 拦 |
| `200 - 400 -1,000` 解析失败，整页被隔离 | **千分位逗号**打断区间正则 | ✅ 解析前统一 `replace(",", "").replace("，", "")` |
| `ap=100~220` | 把 vc 放进了 ap 列 | ✅ 值域（ap ≤25mm）+ 该列最大值分布检查 |
| `S='150 -'` / `vc='50-'` | 区间右端在下一个 span，没聚合 | ✅ 按 x 间距聚合，别按 y |
| `vc=-9` / `fz=-15` | 原文 `0.3-9`，左端被吃掉 | ✅ 正则必须能匹配 `\d+\.?\d*` 而不是 `\d+` |
| `RE=1.6` 三行，原文该处没有值 | 从上一行串过来的（值串行） | ✅ 合并单元格回退只在「向上 60pt 内」且该行**本列确实为空**；不能无条件继承 |
| 型号被截断成 `CTFVR/L2525-3T...` | 版式里就是范围标题 | ✅ 完整照抄不截断；截断行**不删除**、标 `_备注=范围标题/疑似误抽` |
| `-` 和 `0` 混在数值列 | 原文 `-` 表示「不适用」 | ✅ 统一归一化为空；`WF=0` 这种是「无」不是「0 毫米」 |
| 同一型号出现 4 次 | 同一牌号在 P 区和 M 区各印一次，脚本按文字块各抽一行 | ✅ 按主键聚合，不要按文字块 |
| 一个格子堆了两个牌号 | 材质单元格上下堆叠 | ✅ 一行 = 一个牌号，按 y 拆成两行 |
| 型号列里出现 `MS7025, VP15TF` | 多个牌号挤进型号列 | ✅ R4 规则拦，拆成 `grade` 多值 |
| `PR1025 (PR930)` 匹配不上牌号 | 带别名 | ✅ 拆成 `grade=PR1025` + `grade_alias=PR930` |
| `奧氏体` / `奥氏体` 两种写法 | 繁简混排 | ✅ 抽完统一归一化，否则下游按材料筛必漏 |
| `F,U` vs `F, U`、`( 负角)` | 空格差异 | ✅ `norm_label()` 统一：去多余空格、中点 `・`→`·`、`/等`→`等` |
| 页脚 `※` 注释推翻表里的值 | 条件性参数 | ✅ 页级语义抽成列（`note` / `ap_basis` / `scope`），下游必须读 |

## 五、流程与协作

| 现象 | 根因 | 解法 |
|---|---|---|
| 「抽完了」但关键列 97.7% 是空 | 验收只看行数 | ✅ 验收看**每列非空率 + 分母** |
| 行数、页数、覆盖率全对，但数据是空的 | 只比行数；`fields` 取错字典一侧会让身份列全空而行数不变 | ✅ **值级多重集比对**，`只在新产出` 和 `只在参照` 都必须为 0 |
| 报错指向数据，其实是配置问题 | 「vc 不是三元组」的真实原因是表头行数 | 报错信息要带上下文（该行原始单元格、表头行数） |
| 校验大面积假阳性，值明明在原文里 | 只归一化了 CSV 一侧，原文侧还是繁体/全角/中点 | ✅ haystack 也要过同一套归一化（`奧→奥`、`・→·`、全角→半角） |
| 验收报告全 ✅，实际不能用 | 校验只做了「能跑通」 | ✅ 必须有 A/B/C/D 四层，且报告要有「已知问题」节 |
| 改了解析器，行数没变但少了一页 | 静默丢页 | ✅ 回归基线记「总行数 + 页数 + 表块数」 |
| 验的和导的不是同一份 | 校验脚本和落盘脚本分开跑 | ✅ 主表只能从「校验+落盘」那一个脚本出 |
| 两个 AI 同时改同一批脚本互相覆盖 | 无文件归属 | ✅ 建 `_分工边界.md`：谁在维护哪些文件、哪些是只读输入、未认领工作登记 |
| 旧产出被覆盖，无法对照/回滚 | 直接写回原路径 | ✅ 新产出写 `_v2`，旧文件故意留着 |
| 一次性铺开 38 页，全都抽不对 | 版式没分组 | ✅ 一种版式先 1 页做通，再扩到整组；每批抽完停下报告 |
| 整册漏扫 | 只看了目录里提到的那几册 | ✅ 勘察第一步 `ls` 全部册，列「册 → 页数 → 章节数」 |
| 下游按「刀片型号」查不到车削参数 | 口径假设错 | ✅ 京瓷车削参数只出现在刀杆/整体刀具页，键是「刀杆型号 + 刀片材质 + 工件材料」。样本支持不了的口径要**先说清**，别硬做 |

## 六、单位与量级（最容易误判成 bug 的地方）

| 现象 | 真相 |
|---|---|
| `vc = 3 / 4 / 6` 看着不可能 | 微钻（dc=0.05–0.16, n=20000）的**真实值**，值域规则设太窄导致的误报 |
| `ap = 100~220` 看着像 vc | 确实串列了，真 ap ≤25 |
| 转速 `20000` 看着像错 | 微径刀具真实值，判据要用 `n = 1000·Vc/(π·DC)` 反算 |
| `f` 是每转还是每刃 | 表头必须确认（`mm/rev` vs `mm/t`），混用会让下游算错进给速度 |
| 切槽的「切深」 | **不是 ap，是刃宽**。接配刀时不能套用车削的字段模型 |

> 值域规则要**按册/按工序**设，一本样本一套阈值。用全局阈值会把真值判成错值，
> 然后你会去「修」一个本来正确的抽取器。
