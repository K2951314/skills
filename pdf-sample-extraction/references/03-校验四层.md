# 03 校验四层

> 校验的目的不是「证明抽取器没错」，是**主动去找它错在哪**。
> 只跑「能跑通」的检查等于没检查。

## 四层，各判各的

| 层 | 判什么 | 强度 | 能抓什么 |
|---|---|---|---|
| **A 回原文** | 值在原文里真的存在 | 硬 | 凭空造值、跨行串值 |
| **B 值域** | 值在物理上说得通 | 硬 | 列错位、量级错（把 TPI 当 vc） |
| **C 身份列单向包含** | 分类值没跑到别的列 | 硬 | 列归属错、括号拆字 |
| **D 物理不变量** | 列间关系成立 | 最硬 | 三列没放对同一行 |
| **E 几何配对** | 子行 ↔ 参数组的顺序 | **软，人眼** | 最近邻认错行 |

### A 和 B 必须各自独立判

真实事故：`vc = '64 - 12'`。回原文校验——原文里确实有 `64-12`（那是**每英寸牙数 TPI**），
所以 A 层通过。但 vc=64~12 违反 `min < max`，B 层该拦。

当时 `_report_cutparam.py` 写成了「文字匹配就 `continue`」，B 层直接被跳过。
改成独立判定后，才暴露出 p943/p949/p958 三页的 TPI 列被当成 vc。

> **能匹配 ≠ 放对了列。** 这两层永远不能写成 if/else 的短路关系。

### C 层只做单向包含

CSV 的每个分类值必须在原文该列文本里出现（去空白/斜杠/括号后）。
**不做反向覆盖**：页脚注释（`以下使用。切深和进给请参考低碳钢。`）和括号拆字会污染原文侧，
反向判全是假报错。

⚠ **归一化必须两边都做**。CSV 侧做了「奧→奥、・→·、全角→半角」，拿**未归一化的原文**当 haystack，
会把「归一化」本身误判成「值不存在」——p353 的 `不锈钢/(奥氏体系)` 原文是繁体「奧」，
直接比必然报 BAD。`verify_run.py` 的 `squash()` 对两边施加同一套 `GLYPH_FIX` 就是为这个。
**同理，A 层的数字流、C 层的关键词计数，凡是有归一化步骤的，两边都要过一遍。**

### D 层：找一条物理不变量

这是唯一能真正证明「多列放对了同一行」的检查。样本里很多列是互相算出来的：

| 关系 | 式子 | 容差 |
|---|---|---|
| 转速 = f(Vc, 加工径) | `n = 1000·Vc/(π·DC)` | 3~5%（样本取整到 10 转） |
| 每齿进给 = f(进给速度, 齿数, 转速) | `vf = fz·z·n` | 3~5% |
| 加工时间 = f(长度, 进给) | — | — |
| 维度集合对账 | 源表每个非 `-` 单元格 ↔ 输出一个维度组合 | 必须完全相等 |

**维度集合对账**（京瓷 p874）：Vc 组合源 32 / CSV 32，f 组合源 210 / CSV 210。
这条比「行数对不对」强得多——行数可以靠重复凑。

⚠ 容差要分两档：≤5% 视为样本取整；>5% 是**样本自身矛盾**，单独出清单（见下），不算抽取失败。

## 块级连坐

一个表块（一页里的一整张表）里只要**一条**值没过 A 或 B：

```
整块 → 低置信表（附 _err 列写明哪条、什么错）→ 不进主表
```

为什么不是只丢那一条：单条丢弃会把「整列错位」伪装成「少量脏值」。
泰珂洛 p524 螺纹表整列错位时，如果只丢单条，主表会留下 20 行看起来正常的错数据。

隔离 ≠ 放弃。低置信表要带够信息让下一轮能单独写解析器：
`page / src_row / 原文值 / 报错原因 / 已识别的身份列`。

## 自写校验器的 6 个 bug（都是自己写出来的）

| bug | 现象 | 解法 |
|---|---|---|
| `NUM_RE` 带 `^...$` | `findall` 等价整串匹配，`'250 - '` 里的数字全丢，p515 直接 0 行锚点 | 取数用**无锚点**正则 |
| 滑动窗口取三连 | 6 组时产生 (1,2,3) 这种垃圾组合 → 假报「只在原文 9 条」 | 不重叠切块 `range(0, n-2, 3)` |
| 行聚类按相邻间距 | 链式串行：135.3→138.8→142.0→143.5 每步 <dy，两行并成一行 | 和**簇首**比 |
| 行聚类容差拍脑袋 | 2.5 漏折行格（差 2.6）；4.0 把一行劈两半 | 用实测三值夹死（0.22 / 2.6 / 3.97 → 取 3.2） |
| 页脚注释被吸进列 | f 变成 `0.1 - 0.15 - 0.25FF`、form 变成整句中文 | 卡死表体 bbox，并补锚点（否则「切削领域」被 form 列抢走） |
| 用唯一 y 认行 | 灰口铸铁与球墨铸铁的三元组**完全相同**，按 y 找会错配 | 用**多重集**比，不按坐标认行 |

还有一条不是 bug 但必须记住：**单值单元格垂直居中**。
p514 的单值材质 `PR1725` 垂直居中于两个子行之间（y=123.6，参数行在 120.4 / 128.3），
最近邻会认错行。规则：只有 1 个值的列**整格共用**，不做最近邻。

## 校验线要独立于抽取线

最强的校验是**换一条完全不同的路重建**，再和 CSV 对账：

- 抽取用 `find_tables()`，校验就**不用** `find_tables()`，改从原始 span 重建。
- 抽取用「列锚点最近邻」定列，校验就改用**行内数字切块**。

后者在 p353 上能救回来：vc 的 `200` 落在 x=391.7，离 ap 锚点(422.2) 比离 vc 锚点(347.6) **更近**，
最近邻当场把三元组断成 `100-150-`。

行内数字切块的做法：

```
一条视觉行 = [刀尖R × k] + [vc × k] + [ap × k] + [f × k]
刀尖R 是单值且总在最左 → 用 len % 3 丢掉左侧多余数字 → 剩下每 3 个切一组
再要求 CSV 的 (vc, ap, f) 是同一行里连续的三组，顺序必须是 vc→ap→f
```

这样完全不依赖列 x 边界（p353 的 vc 首个数字 x=342.4 比表头锚点 347.6 还靠左 5pt，
任何「锚点 − 5」的写法都会漏掉它）。

## 回归基线

改解析器前后必跑，否则会**静默丢页**（不报错、行数只少一点，很容易被忽略）。

```
snap   →  _baseline.json（行数 / 页数 / 表块数 / 每页行数指纹）
check  →  逐页对比，少一页就非零退出
```

基线要记三个数：**总行数、页数、表块数**。只看总行数不够——
改 A 页多 5 行、改 B 页少 5 行，总数不变。

## 源数据矛盾：不改数据，只出清单

样本自己印错的，主表必须与样本一致（否则下游对不上纸面），另出 `_矛盾清单.csv`。

真实例子（京瓷 p834/p835）：

| 页 | 材料 / 牌号 | 现象 |
|---|---|---|
| 834 | 球墨铸铁 PR1535/PR1525 | Vc 印 `40-100`，但 ø14 转速印 `900-2750`；按 vc=100 应为 **2274** |
| 835 | 碳钢 PR1525 | Vc 印 `80-150`，转速却复用低碳钢的 `3,180-7,160`（那对应 **vc=180**） |

渲染图能直接看到 p835 的低碳钢与碳钢两行转速完全一样、只有 Vc 不同 → 样本自身的印刷/取整问题。
下游要用 rpm 之前先看这份清单，或者干脆用 vc + dc 自己算。

## 验收报告模板

```markdown
# <品牌> <数据类> 抽取验收报告

## 一、验收数字（分母写清）

| 指标 | 旧产出 | 新产出 | 判定 |
|---|---|---|---|
| 覆盖页数 | 69 | 70 | ✅ |
| 数据行 | 640 | 835 | ✅ |
| ap 非空率（分母=**有 ap 列的行**） | 2.3% | 100.0%（204/204） | ✅ |
| 三值齐全 | 15 行 | 168 行 | ✅ |
| 身份列回原文匹配 | 未测 | 8/8 列 100% | ✅ |
| 参数值回原文匹配 | 未测 | ap 100% / f 100% / vc 99.9% | ✅ |
| 被隔离的低置信块 | — | 3 块（20 行） | ⚠ 见 §5 |

## 二、列模型（版式要点）
## 三、防误命中闸门
## 四、校验方法（逐层 + 结果）
## 五、已知问题（未解决，别当已完成）
## 六、复现命令
```

**第五节必须存在**。一份全是 ✅ 的验收报告，通常意味着校验没设计好。
